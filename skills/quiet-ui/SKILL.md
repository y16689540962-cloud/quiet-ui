# quiet-ui

AI 写界面时习惯补一句解释，怕用户看不懂。这些字删掉，页面照样能用，这里处理的就是它们。

适用范围：网页、应用界面、仪表盘、图表、落地页、游戏 HUD。
不适用：文档、邮件、博客、说明书，那里该解释就得解释。

---

## 一、六条硬规则

违反任意一条，整段重写，不要局部打补丁。

1. **页面文字只允许七类**：标题、字段标签、按钮动词、真实数据、错误提示、空状态、法律必需文字。
2. **不加副标题、图注、辅助说明、提示框、眉标签**。要解释的东西交给层级、分组、留白、图标、默认值。
3. **不加问候语、页脚废话（Made with / Powered by）、"Demo data""仅供参考"标签、页面底部小结。**
4. **不用 "·" "•" "|" 把小字串成一句**。一条信息一行；一行说不完就删。
5. **保留 `aria-label`、图片 `alt`、输入框的可见 label**。删字不删功能，不删链接，不删按钮。
6. **只生成页面；回复不超过两句话**，不复述页面内容，不解释你做了什么设计。

---

## 二、三问测试

页面上的每一段非七类文字，逐条过这三问：

1. **用户没有这句话，还能完成这个任务吗？** 能 → 删。
2. **标题或布局已经说了吗？** 说了 → 删。
3. **这是一整句话吗**（有主谓宾、有形容词、"帮助/让/轻松/一站式/无缝"）？ 是 → 删，或压成一个名词短语。

**任意一个"是"就删。拿不准就删。**

---

## 三、固定五步流程

不跳步，不合并。

**第 1 步 · 列**
把页面上每段会显示的文字写成清单，一行一条。包括你打算加的。
格式：`位置｜文字`

**第 2 步 · 过滤**
每条跑三问测试，标 `保留` / `删除` / `改写`。
- `保留` 只在它是七类之一时用。
- `改写` 只能陈述页面已经显示的事实：产品自己的词、功能名、绑定的数据。**不许引入新的数字、速度、客户名、认证、评价。**

**第 3 步 · 构建**
只写 `保留` 和 `改写` 过的文字。七类之外的文字一律不写。

**第 4 步 · 审计**
```
python3 scripts/audit_copy.py <文件或目录>
```
目标是 **0 条**。确有理由留下（错误提示、空状态、法律文字、落地页必需的主标题）的，在该行加 `audit:ok` 注释，并在回复的第二句里说明理由。

**第 5 步 · 回复**
两句话以内。第一句：做了什么。第二句：只在有遗留任务时说。

## 四、分组件规则

### 页头
只放：产品名、导航项、当前用户/账户入口。
不加：标语、状态条（"All systems operational"）、版本号串联、问候语。

### 卡片
`标题 + 值/内容`。不加副标题、不加"点击查看详情"。
卡片里的说明文字只有在它是**真实数据的一部分**时保留（例如一段用户写的笔记正文）。

### 图表
图表的标题说指标名即可（"月度营收"），不说图表类型（"月度营收柱状图"）。
删掉：图例解释、网格线说明、脚注、数据来源小字（除非法律要求）。
轴标签、数值、单位保留。

### 表格
表头、单元格数据、排序/筛选控件保留。
删掉：表下方的说明段、列含义解释（表头应自己说清）、"共 N 条"以外的统计小字。

### 表单
每个字段：**可见 label**（`<label for>` 或包裹）+ 输入控件。
删掉：字段下方的辅助说明、格式提示（改成 `placeholder` 里的示例值，或干脆不写）、"我们不会分享你的邮箱"这类放心话。
错误提示保留，且必须具体（"密码至少 8 位"，不是"输入有误"）。

### 空状态
允许一句话说明为什么空 + 一个动作。**这是七类之一，保留。**
不写："这里空空如也，开始创建你的第一条吧 ✨"这种带情绪和 emoji 的。

### 弹窗
标题 + 内容 + 两个动作按钮（一主一次）。
删掉：标题下的解释句、右上角的装饰性说明。

### 页脚
只放：法律链接、版权行、必要的备案号。
删掉：Made with / Powered by / 技术栈 / "Designed with care in ..." / 社交图标串联。

### 仪表盘
指标名 + 数值 + 单位 + 变化量（由数据渲染）。
删掉：指标卡下方的释义（"较上月增长"改成 `+12%` 数据本身）、问候语、时间段说明串联。
状态点/徽章只有**由条件渲染**时才留。

### 工具页
工具栏 = 动词按钮 + 筛选 + 搜索。
删掉：工具栏下方的操作说明、快捷键提示（放进 `title` 或帮助面板）、"小提示"。

### 游戏界面
HUD 只放会变的状态：分数、血量、资源、背包数量。
删掉：操作说明、"按 X 打开背包"、教程文字（教程是另一个界面）。
数字和图标保留，单位可省。

### 落地页
允许：一个主标题、三个功能名 + 各自一句短语、一个动作按钮、导航。
删掉：主标题下的副标题、"Trusted by 10,000+ teams"、客户 logo 墙（除非真实）、编号 01/02/03、眉标签、三个假免责标签。

---

## 五、别矫枉过正

删完之后必须仍然可用。以下任一不成立就是删坏了：

- 每个页面有一个 `<h1>`。
- 每个输入框有可见 label（不是只有 placeholder）。
- 每个按钮的文字是动词（或图标按钮有 `aria-label`）。
- 每个链接有可读文字，不是"了解更多""点击这里"。
- 空状态仍有文字说明。
- 整页不是一片空白。

**没把握时，保留；只删你确定是废话的。**

---

## 六、清理旧项目

1. 先跑审计，拿到基线：`python3 scripts/audit_copy.py <目录>`
2. 只改**可见文字和装饰**。不动逻辑、数据、颜色、间距、布局结构。
3. 一条一条删，每删一条重跑一次审计，确认数字在降。
4. `aria-label`、`alt`、`<label>` 一律不动。如果被删的文字原本是某个图标按钮的唯一名称，先把名字搬进 `aria-label` 再删。
5. 文字来自 i18n 文件或 CMS 时**改源头**，不要在组件里硬写替换值。
6. 跑完复述：删了几条、剩几条、每条剩下的理由。

---

## 七、收尾自检清单

交付前逐条打勾，任何一条不过就回去改：

- [ ] 页面文字全在七类之内
- [ ] 没有副标题、图注、提示框、眉标签
- [ ] 没有问候语、页脚废话、免责标签、底部小结
- [ ] 没有 "·" "•" "|" 串联的碎句
- [ ] 没有硬编码的状态徽章/状态点（由数据渲染的才算）
- [ ] 每个输入框有可见 label
- [ ] 每个按钮有动词，或图标按钮有 `aria-label`
- [ ] 没有编造的数字、客户名、认证、评价
- [ ] 审计脚本 0 条，或有 `audit:ok` 且有理由
- [ ] 回复不超过两句话

## 附：审计脚本能抓什么

`scripts/audit_copy.py`（标准库，无依赖）。`--json` 出机器可读结果，`--budget N` 超限退出码 1。

| 编号 | 抓什么 |
|---|---|
| R1 | 眉标签（小号 + 大写字距） |
| R2 | 编号标记（01 //、Step 3） |
| R3 | `·` `•` `|` 串联（数据对、掩码卡号已排除） |
| R4 | 标题下的副标题 |
| R5 | 辅助说明 / 操作提示 |
| R6 | 问候语 |
| R7 | 营销套话（中英文） |
| R8 | 无出处的数字与背书 |
| R9 | 页面自我描述（"本节说明…"） |
| R10 | 复述自己标题的段落 |
| R11 | 硬编码徽章（NEW / AI / BETA…） |
| R12 | 页脚废话 |
| R13 | Demo data / 仅供参考 |
| R14 | 底部小结 |
| R15 | `<figcaption>` 图注 |
| R16 | placeholder 重复 label |
| R17 | 引号证言 + 头衔署名 |
| R18 | 衔接词（"or continue with"） |
| R19 | 提示框 / callout（错误、警告、空状态已豁免） |
| R20 | shadcn 的 `CardDescription` / `AlertDescription` 等描述组件 |
| R21 | 文字里的箭头 `←` `↑` `→` `↓` `›` `»`（CSS 画的箭头看不到） |

启发式，会误报也会漏报。**它是尺子，不是判官**：0 条不等于干净，只是没被这套规则抓到。
自检：`python3 tests/run_tests.py`。
